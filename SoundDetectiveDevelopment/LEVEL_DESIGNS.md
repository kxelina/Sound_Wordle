# Sound Detective — 夜間異常檔案 / After-hours Cases

設計日期：2026-10-27。D01–D08 是規劃編號。首批核心玩法已落地：D01 → T09、D02 → W07、D05 → W08；其餘五關仍是設計稿。全部不使用商業歌曲，也不屬於音樂修復模式。

首批範圍：T09 統一開放三個 Delay 控制，以可選成因推理及原有分數門檻診斷提供幫助；尚未新增獨立三層音色提示或峰值註記。W07 只做節奏→音高，音色固定；W08 只考節奏並嚴格保留第三拍。以文字結案、復盤及作品收藏作獎勵，沒有另作門禁動畫。下方保留原始構想，未落地的進階構想不視為已完成。

## 設計原則

- 每關有一個值得聽懂的問題，而不只是換一組隱藏旋鈕數值。
- 音色案件可以反覆聽參照；Sound Wordle 則根據口供製作，通關後才揭曉目標。教學示例不播放隱藏答案。
- 不限提交、不設強制倒數、不因求助扣還原分。先判斷聲音成因的選擇題只作可選線索，答錯不鎖操作。
- 入門只開放兩個主要控制；較難版本增加維度，不以極窄數值範圍製造難度。
- 線索一先描述聽感差異，線索二指向控制並提供獨立示例，線索三才提供參考範圍或節奏格位置。
- 新案件若採特徵範圍計分，應標為「還原／建構進度」。它不是經人耳校準的相似度百分比。既有案件的評分方式不因本設計自動更改。
- 通關回饋使用短小事件、證物收藏與一句案件結論；不需要製作完整劇情動畫。

## D01 多出來的一聲 / The Extra Knock

**模式：**可聽參照的音色案件；入門至標準。

**案件：**證人說門外來了好幾個人，但錄下的敲門聲每次都以相同間隔重複，而且越來越輕。其實有幾次真正的敲擊？

**玩家任務：**以一次短促敲擊，加上合適的回聲，重建證物。先提供可選問題：「重複敲擊／回聲／一條很長的尾音？」選擇不影響分數，也不阻擋調整。

**開放控制：**回聲間隔、衰減時間；標準再開放濕聲比例。敲擊本體、音高、節奏均固定。不要要求正好聽到某個回聲數量，因為可聞次數也受耳機與音量影響。

**可用起點：**短音事件，例如 MIDI 45、0.06 秒，快速起音、低 Sustain 和短 Release。Delay 目標可由 0.24 秒間隔、0.65 秒衰減、0.28 mix 起步試聽；這些是待測試參數，不是完成的聲音效果。只用合成的木質敲擊感，不宣稱模擬真實敲門。

**提示示例：**

1. 「後面的聲音是分開出現的，不是一條連續的尾巴。」 / “The later sounds are separate repeats, not one continuous tail.”
2. 「回聲間隔改變兩次聲音之間的空隙；只延長 Release 不會產生新的起音。」 / “Echo spacing changes the gaps. A longer Release does not create new attacks.”
3. 提供間隔的可接受範圍，並在自己的包絡圖上標記重複峰值。

**通關回饋：**檔案蓋章：「一次敲擊，多次回應。」收藏原聲與完成聲的對比。

**開發範圍：**可復用現有短音、Delay 和圖表；增加案件資料與可選推理提示。現有 T01–T08 註冊需先泛化，不能僅新增 JSON 就宣稱已可玩。

## D02 會說話的門鈴 / A Doorbell with a Message

**模式：**隱藏旋律案件；入門至標準。使用自行創作的兩音訊號，不使用歌曲旋律。

**案件：**快遞員只記得：「先是一聲短而高的聲音，隔了一會兒，再是一聲較低、較長的聲音。」兩個聲音組成門禁提示。

**玩家任務：**在卷簾中放入兩個音，拖動音高、位置和長度。第一階段只處理節奏；第二階段開放音高；進階才調明亮度。

**設計草案：**16 格、100 BPM，一個小節。參考可用 G4 → E4，起點格 0／6，長度格 1／3。這些精確位置只在最高提示或通關復盤展示，不直接寫入初始口供。

**提示示例：**

1. 「你放對了兩個音，但第二聲還不夠長。」 / “You have the two notes, but the second one is still too short.”
2. 示範同音高的一短一長，或只顯示兩個音的節奏輪廓，不先洩露目標音高。
3. 提供起點格及音程方向；最後才顯示音名。

**通關回饋：**門禁燈亮起，播放玩家自己的完整門鈴一次，將它收入收藏。

**開發範圍：**復用現有卷簾和單聲部合成。需要把 W02 內建樂句與分段評分改成可從案件資料讀取；不是單純更換標題。

## D03 電線裡的幽靈 / The Wire Ghost

**模式：**隱藏音色案件；標準。

**案件：**一部舊遊戲機送來一個「空心、帶一點嗡聲，卻不尖銳」的電子訊號。你不能靠整體音量把它變對。

**玩家任務：**利用奇偶諧波分布合成該音色，而非抄出每根推桿的唯一答案。

**開放控制：**入門 H2／H3，其餘固定；標準開放 H1–H5。音高和包絡固定，效果關閉。教學可先用兩組同基頻、相近電平的獨立例音示範音色差別。

**計分草案：**在完整開放版本比較正規化奇偶諧波能量、上次諧波占比與明亮度範圍，接受多組諧波配置。不能只看奇數能量比例，否則純正弦也可能誤通過；需同時約束上次諧波能量。安靜與全零仍不能提交。數值範圍待合成試聽後凍結。

**提示示例：**

1. 「目前太接近純哨音，還缺少一些上次諧波。」 / “It is still too close to a pure whistle; some upper harmonics are missing.”
2. 「保留一些奇數諧波，並比較偶數諧波減少後的音色。」 / “Keep some odd harmonics and compare the sound with fewer even harmonics.”
3. 顯示奇偶能量比例的參考帶，不把全部推桿數值直接列為唯一解。

**通關回饋：**「訊號來源：老式電子設備。」展示玩家和參照雖然參數不同，仍符合要求。

**開發範圍：**聲音引擎可復用；新增群組特徵的案件規則。可參考現有 W01 的諧波能量計算，但要與目前逐控制進度清楚區分。

## D04 屋裡下雨了？ / Is It Raining Indoors?

**模式：**自然類隱藏聲音；標準。

**案件：**窗外沒有下雨，證人卻聽到水聲。關鍵是水滴很有規律，中間幾乎沒有連續的雨幕。

**玩家任務：**製作「水管滴水」而非一般雨聲。把注意力從單顆水滴的音色轉向事件時間分布。

**開放控制：**滴水間隔、規律程度；之後加入水滴長度和明亮度。背景雨幕在入門固定為零。

**提示示例：**

1. 「水滴之間的間隔還是太隨機。」 / “The gaps between drops are still too irregular.”
2. 比較同一水滴音色的規律與不規律排程，在時間軸上顯示玩家自己的起音位置。
3. 提供間隔參考帶及可容許的時間抖動，不要求隨機聲音逐樣本一致。

**通關回饋：**證物標籤由「雨聲？」改為「室內滴水」，亮起簡單的管線位置示意。

**開發範圍：**復用現有 `sdDrop` 聲源，但新增滴水事件排程與規律度控制。目前 rain 密度最低 3 次／秒，不能直接拿原範圍當慢速滴水；需要新的資料配方。

## D05 空白的一拍 / The Silent Beat

**模式：**隱藏節奏案件；入門。

**案件：**走廊裡的機械裝置每四拍運作一輪，但第三拍總是沒有聲音。證人一直把停頓當成錄音故障。

**玩家任務：**重建包含休止的節奏。目標是忠實做出這段有空白的訊號，不是把它「修成每拍都有聲音」。

**開放控制：**音符位置及長度；音高、音色、速度固定。每格可加音、刪音、拖動，不強制恰好只能放三個音。

**設計草案：**16 格一小節，在 0／4／12 格有短促敲擊，8 格為休止。完整節奏只在最高提示和復盤展示。使用合成的短促機械聲，不要求真實時鐘或腳步音色。

**提示示例：**

1. 「你在原本應該安靜的位置加了一個聲音。」 / “You added a sound where the pattern should stay silent.”
2. 先顯示四拍標尺，標出一段『需要留白』的區域；不直接亮出整份目標卷簾。
3. 展示三個起音位置，讓玩家自己完成拖動。

**通關回饋：**檔案浮現節奏符號「● ● — ●」，成為後續案件的視覺彩蛋。

**開發範圍：**復用卷簾和短音合成，需要可資料化的節奏目標及對多餘音符的明確提示。與 D02 一起完成 W02 資料化改造更划算。

## D06 被交換的房間 / The Swapped Rooms

**模式：**空間推理的音色案件；標準至進階。

**案件：**兩段證物的聲源不同：一段是短促敲擊，另一段是較長的電子音。標籤被交換了，你要讓第二種聲音聽起來處於第一段證物所描述的同一種合成空間。

**玩家任務：**從短聲的殘響理解空間，再把該空間感套在另一個固定聲源上。不是清除歌曲混響，也不聲稱推算真實房間尺寸。

**開放控制：**Reverb room、damping、mix；兩個聲源的諧波／包絡鎖定。

**提示示例：**

1. 「短敲擊後留有明顯尾音；你的另一個聲音仍太乾。」 / “The knock leaves a clear tail; your other sound is still too dry.”
2. 只播放自己的『直達聲 → 尾音』比較，解釋濕聲比例與空間大小不同。
3. 提供房間感和阻尼的參考帶，或逐一標示需要改哪個控制。

**通關回饋：**兩張證物卡被放回同一個房間的檔案袋。

**開發範圍：**可復用現有 Reverb，不需新 DSP；但需兩個不同固定聲源共用同一組效果設定的案件流程。播放與匯出都應保留完整尾音。

## D07 玻璃還是金屬？ / Glass or Metal?

**模式：**樂器／物件類隱藏聲音；標準。

**案件：**桌上只有一張口供：「起音很快，後面是薄而亮的金屬般餘響。」先做出聲音，再討論它像什麼材料。

**玩家任務：**製作一個風格化敲擊聲，學習有些聲音的頻率成分不必是基頻的整數倍。不以正確猜出材料名稱作通關條件。

**開放控制：**入門為明亮度和衰減；標準增加「金屬感」與敲擊雜音。把複雜頻率比例包裝為少數可理解的控制。

**聲源草案：**多個正弦分量配上快速起音和衰減，逐漸由整數倍頻移向非整數比例。可由 1／2.76／5.4 的分量比例開始比較，但須先做實際聲音測試，不能把這些數字當作真實玻璃或金屬的通用模型。

**提示示例：**

1. 「你的聲音還太像穩定的電子音，餘響缺少金屬般的色彩。」 / “It still sounds like a steady electronic tone; the tail needs a more metallic colour.”
2. 教學示例比較整數倍頻與非整數分量，不播放隱藏答案。
3. 提供衰減和金屬感的參考範圍。

**通關回饋：**獲得一件可命名的合成敲擊證物；名稱不參與評分。

**開發範圍：**需要新增非諧波部分音聲源及相關控制，目前八個整數諧波不能直接完整表達。先做聲音原型，再決定是否加入正式章節。

## D08 雨夜裡的密碼 / A Message in the Rain

**模式：**分層場景合成的章末關；進階。

**案件：**雨夜的口供描述了兩件事：窗外持續的小雨，以及室內一段「短、短、長」的電子訊號。單獨做對其中一個還不夠。

**玩家任務：**分別搭建背景和前景，再調整兩者平衡。全為本項目自行生成的短聲景與原創提示音，不是歌曲轉錄。

**流程：**

1. 背景層：設定小雨的密度、明亮度和雨幕。
2. 前景層：在簡單卷簾放入三個原創訊號音，處理音高／長短。
3. 混合：調整前景相對音量，讓訊號清楚但仍能聽到雨。

**控制範圍：**一次只顯示當前層的控制。提供自己聲音的背景 Solo、前景 Solo、合聽，不把兩套完整面板同時塞滿畫面。選定一段共同的短時間軸，背景不足或超出的部分按同一規則補齊。

**提示示例：**

1. 「前景節奏已符合描述，但現在蓋住了背景雨聲。」 / “The foreground rhythm fits, but it now masks the rain.”
2. 對自己的兩層提供 Solo 教學，先確認各層是否達標，再提示相對音量。
3. 顯示每層的目標範圍或節奏提示，不以單一平均分讓其中一層掩蓋另一層的失敗。

**計分草案：**背景、訊號、混合平衡分項分開檢查；每項均需達標。所有評分與匯出使用同一份混合設定。只有各層均達標才播放完整參照聲景。

**通關回饋：**播放玩家合成的完整聲景一次，收入章末收藏。可選擇分享自己匯出的 WAV，但不自動上傳。

**開發範圍：**需要真正的多層合成／時間對齊／相對增益與 Solo，現有獨立 SourcePatch 和單音色卷簾尚不能直接組成此流程。最後做，不作第一批發行的必要項。

## 建議實施順序

1. **D01**：先加入一個故事、聽覺推理和回聲調整完整結合的案件，驗證新增案件註冊及收藏流程。
2. **D02 + D05**：共用一次旋律案件資料化改造，增加音符／停頓玩法，避免所有新增內容都是旋鈕。
3. **D03**：新增以音色特徵範圍接受多解的案件規則，先凍結規則，再安排試玩。
4. **D04 + D06**：分別增加規律事件與雙聲源空間比較，仍可復用大部分聲音引擎。
5. **D07**：先驗證金屬敲擊原型的聽感，再擴充樂器類。
6. **D08**：已有足夠單項案例與試玩資料後，再加入分層章末關。

## 落地前共同檢查

- 先泛化案件註冊、存檔識別、首次復盤與收藏 ID；目前 T01–T08、W01–W06 多處仍有固定清單。
- 每個新增案件至少提供英文、繁體中文的故事、三層提示和控制解釋。
- 用實際 SC 音訊確認初始聲音與參照的差異可聞，教學低／高例音確實只改一項。
- 參照必須通過；指定錯誤答案必須不能誤通過；合理替代解應被接受。更接近目標特徵時進度不應反向降低。
- 文字描述若不足以辨別兩種合理答案，應放寬條件或補充線索，而非要求玩家猜一組沒有依據的精確數值。
- 通關前的目標隱藏、無限提交、取消、失焦停止、難度隔離、舊檔保留及收藏匯出皆需回歸。
- 以上是待實作與待試玩的設計，不是已完成的功能、真實材料辨識能力或使用者研究結果。
